# 吸血鬼幸存者玩法客户端开发任务清单

> 范围：客户端为主。**两种模式**：单机模式（单人·多关卡线性闯关）+ 联机模式（双人·无尽）。
> 单机先落地（阶段 1~4，LocalDriver 驱动）；联机后置（阶段 5 起，复用《服务器开发流程.md》帧同步基建，FrameSyncMgr 驱动）。
> 姊妹文档：`文档/开发记录/服务器开发流程.md`（帧同步塔防，联机阶段可直接复用其帧同步基建与服务器端改动清单）。

## 玩法定义与范围

**核心循环**：操控角色在无限地图上自由移动，武器全自动索敌攻击；敌人随时间成波刷新并不断增强，击杀掉落经验宝石；拾取经验升级，三选一强化武器/被动。
- **单机模式（单人·闯关）**：多关卡线性推进。每关有完成目标（存活限时 / 击杀数 / Boss 击杀），通关解锁下一关；失败本关重试。
- **联机模式（双人·无尽）**：双人同图协作，波次无限递增无胜利条件，全灭即 GameOver，以生存时长/击杀数结算。

**MVP 范围**

| 维度 | 范围 |
| --- | --- |
| 模式 | 单机（单人·多关卡线性闯关）+ 联机（双人·无尽） |
| 人数 | 单机 1 人；联机 2 人（各控一角色同图协作） |
| 单局时长 | 单机：按关卡目标（存活限时/击杀数/Boss 击杀，配置表可调）；联机：无尽（全灭即结束，以生存时长/击杀结算） |
| 武器 | 6 种行为范式（阶段 3），每武器 8 级成长，不做进化合成 |
| 被动 | 6~8 种 |
| 敌人 | 6~8 种变体 + 精英 + 定时 Boss |
| 角色 | 1 个（表结构按多角色设计） |
| 平台 | 纯手机：移动走虚拟摇杆（GameJoystick）；桌面仅开发测试用 |

**明确不做（本期）**：金币入账服务器、养成系统（角色/装备存档养成，仅单机闯关解锁进度的轻量本地记录）、武器进化合成、重投/跳过/封禁选牌、地图障碍物、单机双人。
> 注：联机服务器帧同步本期不做但为**规划模式**（阶段 5 落地，复用《服务器开发流程.md》帧同步基建）；单机闯关即多关卡制，不再受"多关卡"排除。

## 总体架构决策（先定后做）

1. **逻辑层/表现层分离**：沿用塔防 BattleLogic/BattleTD 范式。`VampireLogic` 纯 C#（零 UnityEngine 依赖）跑全部战斗逻辑；`VampireView` 表现层只做视图对账、特效、UI。理由：联机帧同步，确定性必须从第一天就是架构属性，后期补不动。
2. **模式-驱动映射（单机先落地，联机后置）**：

   | 模式 | 参战 | 驱动器 | 规则 | 种子/起始帧 |
   | --- | --- | --- | --- | --- |
   | 单机·闯关 | 1 | `LocalDriver`（阶段 1-3，已完成） | 多关卡线性推进 | 本地生成并日志留档 |
   | 联机·无尽 | 2 | `FrameSyncMgr`（阶段 5 接入） | 无尽波次，全灭即结束 | 服务器 `StartGamePush` 统一下发 |

   同一 `VampireLogic.Tick(frame, inputs)` 双驱动零改动，接口形状已对齐 `FrameSyncMgr.OnFrame`。
3. **逻辑帧 33ms（30 帧/秒）**：比塔防 50ms 更适合动作玩法（最终取值见"待定决策"）。常量收口一处，联机时与服务器对齐。
4. **输入抽象 `IBattleInput`**：输出归一化定点方向向量。纯手机项目无 WASD，虚拟摇杆（`GameJoystick`，P1）/ （联机）网络帧输入都实现该接口。输入只在帧边界采样进 Tick，逻辑层禁止读 `Input.*`。
5. **无限地图**：无边界、无障碍（MVP）。表现层背景平铺跟随相机。
6. **实体模型**：逻辑层有序 `List` + 标记死亡 + 每帧末集中清扫（与 BattleLogic 一致）；实体用稳定自增 ID，视图对账按 ID 增删（防 ABA 加版本号，若直接 RemoveAll 则不需要）。表现层直接用现成 `ViewSync<TLogic,TView>` 对账器（TD/VS 共用，异步实体 spawn 返回 null + Attach 补挂），prefab 实体走 `GameMgr.EntityPool` 池化
7. **数值全配置化**：Luban 表驱动，代码不出现玩法数值。Luban 生成的 bean 是纯 C# 类，Logic 直接持有只读引用；联机时服务器用 `-t all` 共享同一份表定义。
8. **武器 = 行为范式 × 目标策略**：范式三种（弹道型 / 瞬时判定型 / 持续区域型）× 目标策略（最近/随机/面朝/移动方向），新武器 = 配表 + 参数分支，不做每武器一个类。
9. **模式规则差异收口在配置/驱动器**：单机闯关（关卡目标判定、通关解锁）与联机无尽（无上限波次、双人协作）共用一套战斗循环与实体体系，差异尽量落在表与驱动器上，避免逻辑层出两套实现。

## 开发约定（必须遵守）

### 确定性纪律（逻辑层 VampireLogic 及其下属结构禁用）

| 禁用 | 替代 |
| --- | --- |
| float / double | `Fix`；常量 `Fix.FromDouble(x)` 仅限初始化 |
| UnityEngine.Random / System.Random | `XRng` + 开局种子（单机种子本地生成并日志留档；联机种子服务器下发，双端一致） |
| Time.deltaTime / Time.time | 逻辑帧号计数换算 |
| Physics / 物理组件 | 圆形碰撞自研（Fix 距离平方比较） |
| Dictionary 遍历 / LINQ / foreach 闭包 | 有序 List、for 循环 |
| 装箱 / Tick 内 new / 字符串拼接 | 池化、预分配（Tick 零 GC 目标） |

### 项目规范

- 日志统一 `Log.Info/Warning/Error`，禁用 `UnityEngine.Debug.Log*`
- 热更脚本只挂 Addressables 场景/prefab，Build Settings 主包场景不挂
- Update 驱动统一走 `CoreMgr.Update`（`IUpdateable`），禁止业务 MonoBehaviour 自建 Update
- 新 UI：`#UIPanel.xlsx` 加行 -> ToolBox 导表 -> prefab 挂 `UIPanelBase` 子类 -> `GameMgr.UI.PanelOn(DPnlId.Xxx)`
- 新配置表：`DataTables/Datas/` 加 xlsx -> ToolBox 导表（自动补全 `DataTableMgr` 属性）
- 新实体资源入 `Remote_Entity` 组；新 UI 入 `Remote_BattlePanel` 组；新场景入 `Remote_Scene` 组
- 表现层读逻辑层数据只允许 `Fix.AsFloat` 转换；逻辑层禁止引用 GameObject/Transform/prefab

## 阶段 4：单机闯关模式（多关卡线性推进）

**目标**：单人按关卡制游玩：每关有完成目标（存活限时/击杀数/Boss 击杀），通关解锁下一关，失败本关重试。纯单机 `LocalDriver` 驱动，无联机依赖。

- [ ] 4-1 关卡配置表（`TbVSStage` 扩展为关卡制）：关卡序列定义，每关 = 目标类型（存活限时/击杀数/Boss 击杀）、目标值、时长上限、敌种构成、强度系数、Boss 时间点（可选）
- [ ] 4-2 关卡目标判定（逻辑层）：按关卡目标类型结算胜负——到时未完成/全灭 = 失败；达成目标值 = 通关；GameOver 区分"胜利通关/失败"
- [ ] 4-3 关卡进度与解锁：通关解锁下一关；本地轻量进度记录（仅存解锁到的关卡数，不引入养成系统）；关卡选择入口（阶段 6 正式 UI，前期临时/TTTT 可调）
- [ ] 4-4 跨关成长（待拍板）：通关后是否保留局内成长（保留则下一关更强起点，需跨关快照逻辑与表支撑；不保留则每关全新开局）
- [ ] 4-5 单机通关/失败流程：通关表现（阶段 6 正式化）+ 下一关入口；失败 -> 本关重试/退主界面
- [ ] 4-6 关卡强度平衡初调：前几关可轻松通过、逐步加压（纯调表）

**验收**：单人从第 1 关可连续打至第 3 关以上；各目标类型判定正确；通关解锁记录正确（重启后仍在）；失败重试正常；退出战斗无泄漏。

## 阶段 5：联机模式（双人·无尽）

**目标**：双人同图协作无尽生存，复用塔防帧同步链路（《服务器开发流程.md》）。驱动器从 `LocalDriver` 换成 `FrameSyncMgr`，`VampireLogic`/表现层零改动（阶段 1-3 已验证接口形状对齐）。全灭即 GameOver，以生存时长/击杀结算。

- [ ] 5-1 驱动器切换：`VampireView` 改由 `FrameSyncMgr.OnFrame` 驱动（替换 `LocalDriver`，`Logic.Tick(frame, inputs)` 不变）；种子/起始帧/参战玩家从 `StartGamePush` 获取（对齐 `TdView` 读取 Room 字段）；`BattleMgr.EnterBattle` 联机路径分支、`ProcedureBattle` 联机入口
- [ ] 5-2 联机输入：网络帧 `inputs` 供给 Tick（`VsInput` 列表形状已对齐帧同步）；输入序列化定稿（16 方向 or 定点 xy 向量，见 8-2）；`PlayerInput` 协议扩展点（对齐服务器文档，见"联机改造备忘"）
- [ ] 5-3 双玩家实体：各自 HP/武器/被动；经验池策略定稿（共享 vs 独立，倾向共享对齐 VS 联机设计，联机同步最简）；双人倒地/复活（见 5-5）与升级选牌同步处理（联机暂停 = 服务器停发帧，对齐服务器文档"战斗暂停机制"）
- [ ] 5-4 联机相机：各客户端只跟随**本地玩家**（替换阶段 4 同屏策略；联机后仅换跟随目标为本地玩家）
- [ ] 5-5 倒地与复活：HP 归零倒地（不立即结束），队友触碰复活（复活次数上限 + 复活无敌帧）；全灭才 GameOver
- [ ] 5-6 无尽波次调度：波次无限递增、强度曲线无上限（表格配置上限拍板）；无胜利条件，双人全灭即结束；强度成长随存活时间持续加压
- [ ] 5-7 确定性验证：同种子录输入流 -> 本地双实例/双开重放 -> `StateHash` 全程一致（顺带成为复现 bug 的调试工具，对应 8-1）
- [ ] 5-8 双人结算：生存时长/击杀数/分数统计（胜负共用，各自统计击杀/伤害）；临时 IMGUI 结算，阶段 6 换正式面板
- [ ] 5-9 断线与重连（基础）：掉线处理（本局标记/结算）、重连后从服务器当前帧继续；双端状态一致性校验（哈希对齐）

**验收**：双人联机完整游玩一局无尽；双端 `StateHash` 全程一致；倒地-复活链路可用；断线/重连不崩不不同步；单机模式（阶段 1~4）无回归。

## 阶段 6：流程闭环与 UI 完善（单机/联机双入口）

**目标**：从主界面到结算再到重开的全流程正式化，覆盖单机闯关与联机无尽两模式，去掉所有临时实现。

- [ ] 6-1 主界面玩法入口正式化：模式选择（单机闯关 / 联机无尽）；单机进入关卡选择（读阶段 4-3 进度）；联机进入建房/匹配（复用 `RoomMgr`）；均复用 Loading 流程
- [ ] 6-2 角色选择面板（最小：1~2 角色，展示初始武器/属性）
- [ ] 6-3 `SettlePanel` 结算面板：单机（关卡结果/解锁下一关/重试）、联机（生存时长/击杀/分数/双人各自统计）；金币字段先本地展示不入账
- [ ] 6-4 暂停菜单：继续/重开/退出（驱动器暂停；表现动画统一用 unscaled 时间）

- [ ] 6-7 移除全部临时 IMGUI 调试 UI（或收进开发开关）
- [ ] 6-8 （可选）手柄支持（纯手机项目以虚拟摇杆为主，手柄预留）

**验收**：选模式 -> （单机：选关 / 联机：建房匹配）-> 选角色 -> 战斗 -> 结算 -> 重开全流程闭环；战斗中直接退主界面无泄漏无报错；两模式互不干扰。

## 关键设计决策存档

| 决策 | 理由 |
| --- | --- |
| 逻辑/表现分离 + 固定逻辑帧 + 本地驱动器 | 为联机帧同步铺路；单机期零成本获得可复现调试（录输入重放） |
| 模式-驱动映射：单机 `LocalDriver` / 联机 `FrameSyncMgr`（2026-08-31 定） | 同一 `VampireLogic` 双驱动零改动；单机先落地联机后置，确定性从第一天是架构属性 |
| 单机闯关 vs 联机无尽（2026-08-31 定） | 单机单人关卡制（有胜负、通关解锁）；联机双人无尽（全灭即结束、以时长/击杀结算）；共享战斗循环基底，规则差异收口在表与驱动 |
| 废弃旧 Entity 范式，表现层收敛 EntityPool + ViewSync（2026-08-26） | EntityMgr 池化设施保留改造为 EntityPool（池化角色/怪物/子弹的表现对象）；BattleTD 字典对账提炼为 ViewSync 通用对账器，TD/VS 共用不出现第三套实体体系；实体对象只有表现无逻辑，阶段 7 换 Instanced 渲染只动资源层 |
| 共享经验池（双人/联机候选） | 对齐 VS 联机设计；联机时等级/选牌同步逻辑最简（阶段 5 拍板） |
| 无限地图无障碍 | MVP 实现最省；障碍碰撞留待玩法验证后加 |
| Luban bean 直读进 Logic | Luban 生成类为纯 C# 只读，联机时 `-t all` 服务器共享同一份定义 |
| 武器 = 范式 × 目标策略 | 新武器 = 配表 + 参数分支，控制类膨胀 |
| 标记 + 集中清扫（有序 List） | 与 BattleLogic 确定性序一致；300 量级 O(n) 清扫无压力 |
| 空间网格放阶段 7 | 先暴力保正确，网格是纯优化可回退，避免早期过度设计 |

## 待定决策（开发中拍板）

- **逻辑帧 33ms vs 50ms**：33ms 手感更好；50ms 可直接复用现有服务器攒批常量，联机时服务器零改动。建议：单机期 33ms 跑手感，阶段 5 联机接入时统一拍板
- **单机跨关成长**（阶段 4-4）：通关后是否保留局内成长（保留=下一关更强起点；不保留=每关全新开局）
- **联机经验池策略**（阶段 5-3）：共享（对齐 VS 联机设计）vs 各自独立
- **联机无尽强度上限**（阶段 5-6）：波次/敌人属性无上限曲线是否设表格上限（防数值溢出与手感崩塌）
- **联机重连深度**（阶段 5-9）：基础重连 vs 掉线期间 AI 托管等增强
- 双人相机：联机各跟随本地玩家（已定）无需同屏夹紧/分屏方案
- 手柄支持优先级（可选项，阶段 6 后评估）
- 渲染方案（1-1 实测后定：GameObject 池 vs Instanced）
- 角色/武器/敌人最终内容规模
