# 吸血鬼幸存者玩法客户端开发任务清单

> 范围：仅客户端。服务器/联机本期不做，但架构为其预留（见"总体架构决策"）。
> 姊妹文档：`文档/开发记录/服务器开发流程.md`（帧同步塔防，联机阶段可直接复用其帧同步基建）。

## 玩法定义与范围

**核心循环**：操控角色在无限地图上自由移动，武器全自动索敌攻击；敌人随时间成波刷新并不断增强，击杀掉落经验宝石；拾取经验升级，三选一强化武器/被动；存活到规定时间胜利，全灭失败。

**MVP 范围**

| 维度 | 范围 |
| --- | --- |
| 人数 | 单人 + 双人（同机本地双人：各控一角色，同屏协作） |
| 单局时长 | 15 分钟（配置表可调） |
| 武器 | 6 种行为范式（阶段 3），每武器 8 级成长，不做进化合成 |
| 被动 | 6~8 种 |
| 敌人 | 6~8 种变体 + 精英 + 定时 Boss |
| 角色 | 1 个（表结构按多角色设计） |
| 平台 | 先桌面键盘；移动端虚拟摇杆列为后期任务 |

**明确不做（本期）**：联机服务器帧同步、金币入账服务器、存档养成、武器进化合成、重投/跳过/封禁选牌、地图障碍物、多关卡。

## 总体架构决策（先定后做）

1. **模拟层/表现层分离**：沿用塔防 BattleSim/BattleTD 范式。`VampireSim` 纯 C#（零 UnityEngine 依赖）跑全部战斗逻辑；`BattleVampire` 表现层只做视图对账、特效、UI。理由：后续双人联机走帧同步（服务器文档阶段 5），确定性必须从第一天就是架构属性，后期补不动。
2. **本地驱动器可替换**：新增 `LocalDriver`（`IUpdateable`，墙钟累积固定步长，帧号从 1 递增）驱动 `VampireSim.Tick(frame, inputs)`，接口形状与 `FrameSyncMgr.OnFrame` 对齐。联机时把驱动器换成 FrameSyncMgr，Sim/表现层零改动。
3. **逻辑帧 33ms（30 帧/秒）**：比塔防 50ms 更适合动作玩法（最终取值见"待定决策"）。常量收口一处，联机时与服务器对齐。
4. **输入抽象 `IBattleInput`**：输出归一化定点方向向量。P1 键盘 / P2 键盘 / 虚拟摇杆 / （未来）网络帧输入都实现该接口。输入只在帧边界采样进 Tick，模拟层禁止读 `Input.*`。
5. **无限地图**：无边界、无障碍（MVP）。表现层背景平铺跟随相机。
6. **实体模型**：模拟层有序 `List` + 标记死亡 + 每帧末集中清扫（与 BattleSim 一致）；实体用稳定自增 ID，视图对账按 ID 增删（防 ABA 加版本号，若直接 RemoveAll 则不需要）。
7. **数值全配置化**：Luban 表驱动，代码不出现玩法数值。Luban 生成的 bean 是纯 C# 类，Sim 直接持有只读引用；联机时服务器用 `-t all` 共享同一份表定义。
8. **武器 = 行为范式 × 目标策略**：范式三种（弹道型 / 瞬时判定型 / 持续区域型）× 目标策略（最近/随机/面朝/移动方向），新武器 = 配表 + 参数分支，不做每武器一个类。

## 开发约定（必须遵守）

### 确定性纪律（模拟层 VampireSim 及其下属结构禁用）

| 禁用 | 替代 |
| --- | --- |
| float / double | `Fix`；常量 `Fix.FromDouble(x)` 仅限初始化 |
| UnityEngine.Random / System.Random | `XRng` + 开局种子（单机种子本地生成并日志留档，便于复现） |
| Time.deltaTime / Time.time | 逻辑帧号计数换算 |
| Physics / 物理组件 | 圆形碰撞自研（Fix 距离平方比较） |
| Dictionary 遍历 / LINQ / foreach 闭包 | 有序 List、for 循环 |
| 装箱 / Tick 内 new / 字符串拼接 | 池化、预分配（Tick 零 GC 目标） |

### 项目规范

- 日志统一 `Log.Info/Warning/Error`，禁用 `UnityEngine.Debug.Log*`
- 热更脚本只挂 Addressables 场景/prefab，Build Settings 主包场景不挂
- Update 驱动统一走 `CoreMgr.Update`（`IUpdateable`），禁止业务 MonoBehaviour 自建 Update
- 新 UI：`#UIPanel.xlsx` 加行 -> ToolBox 导表 -> prefab 挂 `UIPanelBase` 子类 -> `GameMgr.UI.PanelOn(DPnlId.Xxx)`
- 新配置表：`DataTables/Datas/` 加 xlsx -> ToolBox 导表（自动补全 `DataTableMgr` 属性）
- 新实体资源入 `Remote_Entity` 组；新 UI 入 `Remote_BattlePanel` 组；新场景入 `Remote_Scene` 组
- 表现层读模拟层数据只允许 `Fix.AsFloat` 转换；模拟层禁止引用 GameObject/Transform/prefab

## 阶段 1：战斗骨架（最小可跑）

**目标**：进入战斗，P1 键盘移动角色，相机跟随，环形刷怪口追击敌人碰撞伤害，调试 HUD 可见帧号与实体数。

- [ ] 1-0 历史遗留梳理：
  - `BattlePanel.cs` 与废弃 `BattleSurvival` 解耦（输入层按 `CurrentBattle` 类型分支，或拆独立输入组件）
  - `ProcedureBattle.EnterBattle()` 恢复并按 `BattleMode` 分支；`TTTT.cs` 测试触发逻辑标注"仅联机测试场景"
- [ ] 1-1 性能基线验证（定渲染方案）：临时场景 300 个池化 GameObject（SpriteRenderer/图元）每帧位移，桌面 + 真机测帧率并记录结论（GameObject 池够用 / 需 Instanced 渲染），作为阶段 6 依据
- [ ] 1-2 `BattleMode.VampireSurvivor` 枚举；`BattleMgr.EnterBattle(BattleMode)` 分支重载（单机跳过 `Room.StartFrame` 校验）；`BattleVampire : BattleBase` + `VampireSim` 空骨架（Tick/StateHash/Dispose）
- [ ] 1-3 `LocalDriver`：注册 `CoreMgr.Update`，墙钟累积固定步长，帧号从 1 递增，采样输入调 `Sim.Tick`；暂停接口（直接停步进，不动 TimeScale）
- [ ] 1-4 `IBattleInput` 抽象 + `KeyboardInput`（P1: WASD，斜向归一化，输出 Fix 向量）
- [ ] 1-5 玩家实体：SimPlayer（Pos/Radius/MoveSpeed/MaxHp/Hp/Facing），Tick 内移动；表现层视图对账（SyncViews 模式）+ GameObject 池
- [ ] 1-6 相机跟随：BattleCamera 平滑跟随玩家（表现层 lerp）；背景平铺无限滚动
- [ ] 1-7 敌人实体：SimEnemy（追击 AI：朝最近玩家方向移动）、接触伤害（半径判定 + 伤害间隔节流）、死亡标记集中清扫；1 种敌人
- [ ] 1-8 环形刷怪：以相机视野外一圈随机角度生成（XRng），固定间隔刷（数值暂放 Sim 常量区，阶段 2 挪表）
- [ ] 1-9 临时调试 HUD（IMGUI）：帧号、实体数、玩家 HP、每 50 帧 StateHash 日志

**验收**：主界面可进战斗（临时入口即可）；移动/刷怪/追击/碰撞掉血全链路跑通；同屏 100 敌人桌面稳定 60 帧；退出战斗无泄漏（订阅/GameObject 全清）。

## 阶段 2：核心战斗循环

**目标**：打通"刷怪 - 击杀 - 掉宝石 - 升级三选一 - 变强"完整循环，数值全部进表。

- [ ] 2-3 武器框架：武器实例（等级/冷却计时/开火逻辑），范式+目标策略枚举分发，Tick 内固定序遍历

**验收**：1 角色 1 武器 1 敌种可完整玩一局；选牌暂停/恢复正常；数值全部来自表；同屏 200 敌 + 100 弹幕桌面 60 帧；Profiler 确认 Tick 路径零 GC Alloc。

## 关键设计决策存档

| 决策 | 理由 |
| --- | --- |
| 模拟/表现分离 + 固定逻辑帧 + 本地驱动器 | 为联机帧同步铺路；单机期零成本获得可复现调试（录输入重放） |
| 共享经验池（双人） | 对齐 VS 联机设计；联机时等级/选牌同步逻辑最简 |
| 无限地图无障碍 | MVP 实现最省；障碍碰撞留待玩法验证后加 |
| Luban bean 直读进 Sim | Luban 生成类为纯 C# 只读，联机时 `-t all` 服务器共享同一份定义 |
| 武器 = 范式 × 目标策略 | 新武器 = 配表 + 参数分支，控制类膨胀 |
| 标记 + 集中清扫（有序 List） | 与 BattleSim 确定性序一致；300 量级 O(n) 清扫无压力 |
| 空间网格放阶段 6 | 先暴力保正确，网格是纯优化可回退，避免早期过度设计 |
