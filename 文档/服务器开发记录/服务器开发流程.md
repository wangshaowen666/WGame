# 塔防游戏服务器开发记录

## 技术栈

| 模块 | 技术选型 |
|---|---|
| Web API | ASP.NET Core Minimal API (.NET 8) |
| 数据库 | SQLite（开发）→ MySQL（上线） |
| ORM | Dapper |
| 认证 | JWT Token |
| 实时通信 | LiteNetLib（KCP 可靠传输） |
| 帧同步 | 自研（操作攒批 + 广播） |
| 协议序列化 | BinaryWriter/Reader（实时）+ JSON（HTTP） |

## 架构总览

```
┌─────────────────────────────────────────────┐
│              客户端 (Unity)                   │
│                                             │
│  HttpMgr ──────-> 登录/养成分服 ←── ASP.NET Core API
│                        │                    │
│  NetMgr ────────-> 实时游戏服 ←── LiteNetLib + 帧同步
└─────────────────────────────────────────────┘

登录/养成分服（C# 控制台 / Web API）:
├── ASP.NET Core Minimal API
├── SQLite/MySQL + Dapper
├── 账号注册/登录
├── 玩家数据读写（金币、塔等级、通关进度）
└── JWT Token 认证

实时游戏服（C# 控制台）:
├── LiteNetLib
├── 帧同步引擎（操作转发）
├── 游戏开始时从数据库加载玩家数据
└── 游戏结束后保存结算到数据库
```

### 数据库设计

```sql
CREATE TABLE Player (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Username TEXT UNIQUE NOT NULL,
    PasswordHash TEXT NOT NULL,
    CreatedAt DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### API 设计

| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| /register | POST | `{username, password}` | `200 OK` / `400 用户已存在` |
| /login | POST | `{username, password}` | `{token, playerId}` / `401 密码错误` |

### 流程

```
客户端                    登录服务器                数据库
  │                         │                       │
  │── POST /register ──────>│                       │
  │   {user, pass}          │── BCrypt.HashPassword │
  │                         │── INSERT Player ─────>│
  │<── 200 OK ──────────────│                       │
  │                         │                       │
  │── POST /login ─────────>│                       │
  │   {user, pass}          │── SELECT Player ─────>│
  │                         │<── 返回玩家记录 ──────│
  │                         │── BCrypt.Verify        │
  │                         │── 生成 JWT Token       │
  │<── {token, playerId} ───│                       │
```

### 关键知识点

- **BCrypt**：密码哈希算法，不可逆。即使数据库泄漏，攻击者也无法还原密码
- **JWT Token**：无状态认证。服务器不存 Session，Token 自带玩家信息 + 过期时间 + 签名
- **Dapper**：轻量 ORM。`db.QueryAsync<T>("SELECT ...")` 直接映射成 C# 对象

### 参考代码

```csharp
// Program.cs (ASP.NET Core Minimal API)
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<DbHelper>();
var app = builder.Build();

app.MapPost("/register", async (Player req, DbHelper db) =>
{
    var existing = await db.QueryFirstOrDefaultAsync<PlayerData>(
        "SELECT * FROM Player WHERE Username = @u", new { u = req.Username });
    if (existing != null)
        return Results.BadRequest("用户已存在");

    var hash = BCrypt.Net.BCrypt.HashPassword(req.Password);
    await db.ExecuteAsync(
        "INSERT INTO Player (Username, PasswordHash) VALUES (@u, @p)",
        new { u = req.Username, p = hash });
    return Results.Ok();
});

app.MapPost("/login", async (Player req, DbHelper db) =>
{
    var player = await db.QueryFirstOrDefaultAsync<PlayerData>(
        "SELECT * FROM Player WHERE Username = @u", new { u = req.Username });

    if (player == null || !BCrypt.Net.BCrypt.Verify(req.Password, player.PasswordHash))
        return Results.Unauthorized();

    var token = JwtHelper.GenerateToken(player.Id, player.Username);
    return Results.Ok(new { token, playerId = player.Id });
});

app.Run();
```

### 数据库设计

```sql
CREATE TABLE PlayerData (
    PlayerId INTEGER PRIMARY KEY,
    Gold INTEGER DEFAULT 0,
    StageProgress INTEGER DEFAULT 0,
    TowerLevels TEXT DEFAULT '{}',  -- JSON: {"tower_1": 3, "tower_2": 1}
    UpdatedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (PlayerId) REFERENCES Player(Id)
);
```

### API 设计

| 接口 | 方法 | 鉴权 | 请求 | 响应 |
|---|---|---|---|---|
| /data | GET | Bearer Token | - | `{gold, stageProgress, towerLevels}` |
| /data | POST | Bearer Token | `{gold, stageProgress, towerLevels}` | `200 OK` |

### 关键知识点

- **鉴权中间件**：每个请求先验证 Token，从中提取 PlayerId，再处理业务
- **数据所有权**：确保玩家只能读写自己的数据，不能传 PlayerId 修改别人的

### 消息协议

```csharp
public enum MsgType : byte
{
    C2S_Login = 1,        // 登录（带 Token）
    S2C_LoginAck = 2,     // 登录回复
    C2S_Heartbeat = 3,    // 心跳
    S2C_HeartbeatAck = 4, // 心跳回复
    C2S_Input = 5,        // 玩家操作
    S2C_Frame = 6,        // 服务器广播帧
    S2C_StartGame = 7,    // 开始游戏
}
```

### 关键知识点

- **LiteNetLib NetManager**：管理连接，PollEvents 轮询收包
- **ReliableOrdered 模式**：类似 KCP 的可靠有序传输，适合帧同步
- **心跳机制**：客户端每 5 秒发心跳，服务器 15 秒没收到则断线

## 阶段 4：帧同步

**目标**：双人操作通过服务器转发，各客户端确定性执行，画面一致

**学习技能**：帧同步引擎 + 操作攒批 + 帧缓冲 + 确定性逻辑

### 任务清单

- [ ] 定义 PlayerInput 结构（操作类型 + 参数）
- [ ] 定义 FrameData 结构（帧号 + 操作列表）
- [ ] 服务器实现逻辑帧循环（50ms 攒批 + 广播）
- [ ] 服务器实现操作校验
- [ ] 客户端实现帧缓冲（缓冲 2 帧防抖动）
- [ ] 客户端实现逻辑帧驱动（Update 中 50ms 一帧）
- [ ] 业务逻辑改造为确定性（定点数/确定性随机等）

### 帧同步时序

```
客户端A          服务器           客户端B
  │── C2S_Input ─>│                │
  │               │  (50ms 攒批)   │
  │               │<── C2S_Input ──│
  │<── S2C_Frame ─│── S2C_Frame ──>│
  │  执行帧        │                │  执行帧
```

### 确定性约束

| 禁用 | 替代 |
|---|---|
| float/double | 定点数 |
| UnityEngine.Random | 确定性 PRNG + 同步种子 |
| Physics | 自研确定性物理或不用 |
| Dictionary 遍历 | List / 有序结构 |
| Time.deltaTime | 固定逻辑帧（50ms）|
